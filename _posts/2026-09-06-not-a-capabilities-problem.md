*[What Can We Actually Do With AI Agents Right Now?](https://jwildfire.github.io/2026/06/10/rpharma-keynote-developer-diary.html) Quite a lot. Are clinical trials ready to implement these tools? I'm not so sure…*

### What are these models good at?

Throughout this series, I've tried to stay focused on one core question: "What is AI good at right now?" I think the answer is: quite a lot. [Obot](https://jwildfire.github.io/2026/07/13/obot-v3-billion-tokens.html), the agentic framework I created for this project — Claude Code under the hood — has made meaningful progress on every problem I've pointed it at. The biggest win was modernizing [safetyGraphics](https://jwildfire.github.io/2026/06/16/reintroducing-safetygraphics.html) and merging it into the OpenRBQM {gsm} framework via the new [safety.viz](https://jwildfire.github.io/2026/07/12/introducing-safety-viz.html) and [gsm.safety](https://jwildfire.github.io/gsm.safety/). I'd wanted to do that work for years but put it off because I thought it would take a team about a year to refactor so much code. With the current AI tools, I got it done as a side project over the summer. safety.viz went from [zero to thirteen chart renderers across six releases](https://jwildfire.github.io/2026/08/20/obot-v4-second-interview.html) between mid-July and mid-August; [two published clinical workflows became working prototypes in a single evening](https://jwildfire.github.io/2026/07/17/papers-prompts-prototypes.html); and the whole summer ran on a [$200-a-month plan](https://jwildfire.github.io/2026/07/13/obot-v3-billion-tokens.html).[^max] I've had many similar experiences at work in recent months, projects that I'd think would need a day or two now take an hour, and multi-week projects can be developed in a day[^meetings].

Using agentic AI as a cornerstone of clinical development is no longer about capabilities — it's about execution. The models are capable. We've just got to figure out how to bring them into clinical development carefully and safely.

### Closing the execution gap

AI best practices are evolving quickly. The [Model Context Protocol](https://www.anthropic.com/news/model-context-protocol) launched in November 2024 and was [donated to the Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation) a year later. [Agent Skills](https://agentskills.io) became an open standard in December 2025. [Claude Code](https://claude.com/product/claude-code) didn't exist at the start of last year. GxP standards, on the other hand, are built on decades of precedent and evolve slowly by design. [FDA's AI-in-drug-development guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/considerations-use-artificial-intelligence-support-regulatory-decision-making-drug-and-biological), for example, has been a draft since January 2025. The capabilities are becoming obvious; the adoption pathway isn't.

Fortunately, the meaningful progress on precompetitive frameworks for running clinical trials in recent years provides a viable path forward. Tools from this project like [OpenRBQM](https://openrbqm.github.io/) and [safetyGraphics](https://safetygraphics.github.io/) sit alongside [pharmaverse](https://pharmaverse.org), the [R Consortium submissions working group](https://rconsortium.github.io/submissions-wg/), the [R Validation Hub](https://www.pharmar.org), and the [CDISC](https://www.cdisc.org/standards) data standards foundation that has been in development for more than twenty years. Developers across these projects are [already using coding agents](https://pharmaverse.github.io/blog/posts/2026-06-14_admiral_in_age_of_ai/admiral_in_age_of_ai.html) to speed up development of the core frameworks and to build early versions of an agentic scaffold — including [skills](https://github.com/RConsortium/pharma-skills) and [MCP functionality](https://github.com/posit-dev/mcptools) — needed to run them at scale.

The next step is to truly modernize the pipelines that sit behind these tools. While pharmaverse and CDISC form a strong portfolio-level foundation, standards around study-level implementation are much less mature. Moving from legacy scripted statistical programs to configurable R and Python scripts built on GxP-qualified packages is an important first step, but more is needed. Broad adoption of foundational concepts such as version control and semantic versioning is likely a prerequisite for adopting agentic AI at all.

The OpenRBQM framework and projects like the R Validation Hub and the R Consortium submission pilots provide a valuable operational foundation to build on. But in my opinion, the clinical trial community is not ready for the coming conversation about managing the volume of code that agents can now produce. So far, Obot has generated [roughly 315,000 lines of source across 367 pull requests and 23 releases in 12 repositories](https://jwildfire.github.io/2026/07/13/obot-v3-billion-tokens.html) — from one person and a few agents, working in spare time.[^code] I've tried to build GxP best practices into my workflows (more on that in the next entry), but I can't say with confidence how long it would take to fully qualify this work using current standards. I can say that others using agents at scale are wrestling with the same problem — [Addy Osmani](https://www.oreilly.com/radar/agentic-code-review/) and [Milestone](https://mstone.ai/blog/ai-code-review-bottleneck/) both describe review, not writing, as the bottleneck. If agentic coding is overwhelming modern SDLC pipelines, I worry about how it will impact an industry where unversioned scripts and double programming remain in active use.

All told, progress toward a robust software development life cycle for all code written in support of clinical development has been slow, and a unified technical framework — with robust APIs and MCP functionality across the many components involved in clinical development — is just beginning. The same tools cut both ways, though: agentic AI can modernize legacy codebases and help with training and change management. I think that getting statistical programmers to use version control will be significantly less challenging when an agent can handle most of the day-to-day git commands using well documented skills governed by a controlled MCP layer.

### What's next?

I believe the upside for a robust AI-ready precompetitive framework for clinical trials is enormous. Anthropic CEO Dario Amodei's [*Machines of Loving Grace*](https://darioamodei.com/essay/machines-of-loving-grace) argues that AI-enabled biology and medicine could "compress the progress that human biologists would have achieved over the next 50-100 years into 5-10 years." Every discovery those tools produce still has to pass through a clinical trial. If discovery accelerates by even a fraction of what Amodei predicts, our current development pipelines have no chance of keeping up. A compressed century of biology is only possible with a compressed century of trials.

The good news is that my experience suggests the capabilities are real. With these new tools, trial execution can be streamlined so that we can run more trials: more indications, more head-to-head comparisons, rare diseases that never pencil out today, more patients finding a study that fits them. The human effort shifts to discovery, and to the patient's experience of the trial itself.

We're just starting to understand the capabilities and best practices for these tools. If the frontier models were frozen today, clinical trials would still be completely different in five years. Who knows what will be possible as the frontier continues to evolve.[^ai]
