The Rho Graphics Group

A handful of webpages beats a 200-page PDF

Source: diary #3. The "wall of numbers" in a clinical study report was "100% impenetrable" (the post uses a Harry Potter GIF for the feeling). gsm · Good Statistical Monitoring

Monitoring a trial, as software

Sources: diary #1 ("We use the {gsm} tools to monitor actual studies. We wrote a paper and have given a bunch of presentations") and diary #4 ("Unlike {safetyGraphics}, {gsm} was designed for GxP from the start").

What it is: a family of open-source R packages for risk-based quality monitoring: key risk indicators and quality tolerance limits by site, reported as HTML. gsm.core is the analytics engine; workr runs the workflows; qcthat produces the quality-control evidence. The team leads the PHUSE OpenRBQM working group.

The rule that doesn't change

AI-written code still needs a human owner

  • A person owns the requirements.
  • A person owns the risk decision.
  • A person must be able to explain why the code works.
  • A person must be able to explain why it is safe enough for medical research.

Jeremy's steer (2026-10-05): "worth talking at least a little bit about the scaffold, obot.roadmap (goal/requirement/tasks). I review releases and answer questions. I think it really worked quite well in the last weekend session after so many struggles." The headline is his sentence.

What it is: three levels of GitHub issues. An objective is what Jeremy wants; a requirement is sized so one session can finish it, and carries a definition of done; a task is one pull request in the repository where the code lives. Status is a label on the issue: backlog, ready, in session, review, released. Three short standards documents on the hub say how issues are tracked, how sessions run and how code reaches a release.

What a person does (hub, ways of working): "Human driving, not human reviewing. @jwildfire sets the objectives, signs the trees, answers the blocked questions and reviews the release candidates." Before a release candidate reaches him, three reviewer agents read it for correctness, for the definition of done and for the house rules.

The example line: the hub's tracker page, filtered to the objective "Biomarker charts", showed 12 of 12 requirements released and 37 of 37 tasks done on 2026-10-05; its four releases are bio.viz and gsm.bio v0.1.0 and v0.2.0.
